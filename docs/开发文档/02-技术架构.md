# Mini-Todo - 技术架构设计

> 本文描述 3.1+ 的 GPUI 版 PC 端（`pc-gpui/`）、云端服务（`cloud/`）及跨端共享协议（`shared/mini-todo-protocol/`）。
> 接口细节以 `pc-gpui/crates/app/README.md`、`pc-gpui/crates/core/README.md` 与 `cloud/README.md` 为准，
> 约定与契约见 `.trellis/spec/`。1.x ~ 2.x 的 Tauri + Vue 架构已随旧代码删除（见 git 历史）。

## 1. 整体架构

macOS 上同一个 `mini-todo` 二进制（universal）包成 `mini-todo.app`（bundle id `com.tauri-app.mini-todo`，与 2.5.0 mac 版相同）。

## 2. 界面层（crates/app）

### 2.1 窗口

| 模块 | 窗口 |
|---|---|
| `windows/list_window.rs` + `list_window/` | 待办清单窗口（每个清单一个，透明、无系统标题栏）：标题栏、清单名就地改名、列表 / 四象限、行右键移动到清单、FAB、遮罩 |
| `windows/calendar_window.rs` + `calendar_window/` | 独立日历窗口（单例，透明、无系统标题栏）：6×7 月历网格、农历 / 节气 / 节假日、跨天待办条、清单筛选、双击某天新建 |
| `windows/block.rs` / `drag.rs` / `snap.rs` | 清单 / 日历 / 收纳箱共用的自绘拖动、8 方向缩放手柄与窗口吸附组 |
| `windows/editor/` | 待办详情 / 编辑（只读 ⇄ 编辑、表单、清单选择、子任务面板、描述放大编辑） |
| `windows/subtask.rs` | 子任务查看 / 编辑 |
| `windows/completed.rs` | 已完成（按打开方清单过滤，仅查 `completed = 1` 并预计算小写搜索键） |
| `windows/notification.rs` | 应用内通知（透明、置顶、不抢焦点） |
| `windows/settings/` | 设置（常规 / 外观 / 数据与同步含图片清理与可选 E2EE 口令 / 屏幕配置 / 关于） |
| `windows/changelog.rs` | 应用内更新日志 |
| `windows/fence/` | 桌面收纳箱（透明；Windows 嵌入桌面层，macOS 是桌面图标层之上的不激活面板） |

所有窗口由 `windows::WindowManager` 统一登记：模态子窗口（同一打开方同一时刻一个，打开方显示遮罩）、Windows 上以打开方为 owner（macOS 没有 owner 关系）、在打开方所在显示器居中、子窗口关闭后按需刷新数据。所有窗口均为自绘标题栏。

### 2.2 状态管理（`state::AppState`）

`AppState` 是 GPUI 的 `Entity` + Global，所有窗口共享，并通过细粒度版本号（`todos_revision`、`lists_revision`、`settings_revision`、`sync_revision` 与按 `BlockKey` 拆分的 `window_prefs_revisions`）避免无关窗口重绘：

- **选择性重绘**：每个清单窗口和日历窗口只在其关心的版本号变化时才 `cx.notify()`；切换一个清单窗口的深浅色/视图模式不会触发其它窗口重绘。
- **派生视图缓存**：清单窗口缓存 `(total, pending: Vec<RowData>, quadrants)`，日历窗口缓存 `(bars, todo_info)`，仅在数据版本号或月份/筛选变化时重建，悬停、滚动和菜单开关做到零重算。
- **按需刷新**：窗口激活时走 `refresh_if_changed` 比对 `change_seq`，仅在数据库确实变更时拉取。

### 2.3 线程隔离与后台服务（`db.rs`、`services/`）

- `db::spawn_db`：短耗时本地 SQLite 读写，复用 GPUI `background_executor`。
- `db::spawn_io` / `db::spawn_io_db`：长耗时阻塞 I/O（WebDAV 同步、连接测试、更新检查、节假日拉取、ZIP 导入导出、孤儿图片清理）在独立命名 OS 线程执行，经 `async_channel` 回传结果，避免占满 GPUI 后台线程池。
- `services::scheduler`：提醒调度运行在独立 OS 线程（`reminder-scheduler`），不长期占用 GPUI 线程池。
- `services::window_mode` 与 `services::fences`：200ms 守护循环改为按需启停（仅存在固定/嵌入窗口或收纳箱时运行），且仅在存在贴边自动隐藏窗口时枚举显示器。

### 2.4 控件、Markdown 与平台层

- `ui/`：Element Plus 风格共享控件，其中 `ui/markdown.rs` + `ui/markdown/` 拆分为 `markdown.rs`（块模型与布局度量）、`parse.rs`（mdast 解析与缓存）、`image.rs`（图片尺寸正/负缓存与缩放计算）、`render.rs`（视图与手柄渲染）。
- `theme.rs`：颜色 / 字体 / 圆角 / 间距 / 阴影 token 的唯一来源。
- `platform/`：Win32（`windows 0.62`）/ macOS AppKit（`objc2`）/ Linux fallback 窗口能力封装。

## 3. 业务核心（crates/core）与共享协议（shared/mini-todo-protocol）

### 3.1 共享协议（`shared/mini-todo-protocol`）

PC（`mini-todo-core`）与云端（`minitodo-cloud`）共同依赖 `shared/mini-todo-protocol`，消除跨端规则漂移：
- `ids`：JS 安全整数范围内的分布式记录 ID（UNIX 毫秒 × 1000 + 随机后缀）
- `image_name`：K5 安全文件名规则、扩展名白名单与 Content-Type 映射
- `webdav_xml`：WebDAV PROPFIND multistatus XML 解析与 ETag 强弱处理
- `crypto`：可选客户端端到端加密（`MTENC01\0` 魔数头 + PBKDF2-HMAC-SHA256 200,000 次迭代 + ChaCha20-Poly1305 AEAD，明文 gzip 向后兼容）

### 3.2 核心模块结构（`crates/core`）

```
pc-gpui/crates/core/src/
├── lib.rs
├── db/
│   ├── connection.rs         # SQLite WAL 模式、busy_timeout、temp_store=MEMORY、迁移前备份
│   ├── migrations.rs         # 数据库迁移（v1~v31）+ 幂等运行时索引（待提醒部分索引等）
│   ├── models.rs             # 数据模型
│   ├── settings_kv.rs        # settings 读写助手（只在值变化时刷新 updated_at）
│   ├── sync_store.rs + sync_store/ # 拆分为 sync_store.rs / tombstones.rs / parse.rs / merge.rs / tests.rs
│   ├── time.rs               # 规范时间格式解析/规范化
│   ├── paths.rs              # 数据 / 图片目录（K5 校验委托给 mini-todo-protocol）
│   └── backup.rs             # VACUUM INTO 备份（保留最近 5 份）
├── services/                 # webdav.rs（进程级 Client 复用、Bytes 零拷贝重试、流式限长下载）、
│                             # secret.rs（DPAPI）、fence_fs/（Windows Shell / macOS mac.rs）
├── todo.rs                   # 待办 / 子任务 CRUD、`list_completed`、图片保存、未引用孤儿图片清理
├── data.rs                   # 导入导出（v4.1，含 128 MiB 流式防 Zip Bomb 上限）、AppSettings 读写

├── sync/                     # WebDAV 同步（4 路并发图片传输、可选 E2EE）
├── settings.rs / holiday.rs / lunar.rs / reminder.rs / window_logic.rs / fence/
```

## 4. 云端服务（`cloud/`）架构摘要

- **读写分离与异步不阻塞**：SQLite 开启 WAL + `busy_timeout=5000` + `synchronous=NORMAL` + `temp_store=MEMORY`；维护独立的只读连接（`SQLITE_OPEN_READ_ONLY` + `query_only=ON`）与写连接，全部 Axum handler 通过 `run_read` / `run_write`（`tokio::task::spawn_blocking`）访问数据库，响应头中间件合并为单条 `SELECT ... WHERE key IN (...)`。
- **事件驱动推送与限流**：`push_loop` 使用 `tokio::sync::Notify` + 精确去抖/退避截止时间替代轮询；`/sync` 手动触发入口限制最大 4 路并发（超限返回 429）。
- **安全限长与可选 E2EE**：gzip 解压上限 256 MiB、WebDAV 响应上限 128 MiB、图片流式下载上限 64 MiB；支持在 `config.toml` 中配置可选 `sync_passphrase` 与 PC 端互通端到端加密。
