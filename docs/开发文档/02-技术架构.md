# Mini-Todo - 技术架构设计

> 本文描述 3.0 起的 GPUI 版 PC 端（`pc-gpui/`）。接口细节以 `pc-gpui/crates/app/README.md`、`pc-gpui/crates/core/README.md` 为准，
> 约定与契约见 `.trellis/spec/`。1.x ~ 2.x 的 Tauri + Vue 架构已随旧代码删除（见 git 历史）。

## 1. 整体架构

```
┌──────────────────────────────────────────────────────────────┐
│                 mini-todo.exe（单进程）                        │
├──────────────────────────────────────────────────────────────┤
│  crates/app（mini-todo）—— GPUI Application（QuitMode::Explicit）│
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌───────┐│
│  │ windows/ │ │   ui/    │ │ state.rs │ │services/ │ │platform││
│  │ 各窗口   │ │ EP 风格  │ │ AppState │ │托盘/同步/│ │ Win32  ││
│  │ 视图     │ │ 控件     │ │ 全局状态 │ │提醒/收纳箱│ │ 窗口能力││
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘ └───────┘│
│                     │  db::spawn_db（放后台线程）              │
│  crates/core（mini-todo-core）—— 阻塞函数，不依赖 GUI 框架        │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌───────┐│
│  │ db/      │ │ todo /   │ │ sync/    │ │ reminder │ │ fence/ ││
│  │ SQLite   │ │ data     │ │ WebDAV   │ │ settings │ │fence_fs││
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘ └───────┘│
├──────────────────────────────────────────────────────────────┤
│  Windows：DirectX 11 / DirectComposition、DWM、Shell（IFileOperation）、  │
│  Toast、注册表（开机自启）、DPAPI                               │
│  macOS（预览）：Metal、AppKit（objc2：NSWindow / NSScreen / NSEvent）、│
│  UNUserNotificationCenter、LaunchAgent（开机自启）、Unix socket（单实例）│
└──────────────────────────────────────────────────────────────┘
```

macOS 上同一个 `mini-todo` 二进制（universal）包成 `mini-todo.app`（bundle id `com.tauri-app.mini-todo`，与 2.5.0 mac 版相同）。

## 2. 界面层（crates/app）

### 2.1 窗口

| 模块 | 窗口 |
|---|---|
| `windows/main_window.rs` + `main_window/` | 主窗口（透明、无系统标题栏）：标题栏、列表 / 四象限 / 日历、FAB、遮罩 |
| `windows/editor/` | 待办详情 / 编辑（只读 ⇄ 编辑、表单、子任务面板、描述放大编辑） |
| `windows/subtask.rs` | 子任务查看 / 编辑 |
| `windows/completed.rs` | 已完成 |
| `windows/notification.rs` | 应用内通知（透明、置顶、不抢焦点） |
| `windows/settings/` | 设置（常规 / 外观 / 数据与同步 / 屏幕配置 / 关于） |
| `windows/fence/` | 桌面收纳箱（透明、嵌入桌面） |

所有窗口由 `windows::WindowManager` 统一登记：模态子窗口（同一打开方同一时刻一个，打开方显示遮罩）、Windows 上以打开方为 owner
（macOS 没有 owner 关系）、在打开方所在显示器居中、子窗口关闭后刷新数据。所有窗口都是自绘标题栏：Windows 上去掉 `WS_SYSMENU`，
macOS 上建窗后隐藏系统红绿灯。

### 2.2 状态管理（`state::AppState`）

`AppState` 是 GPUI 的 `Entity` + Global，所有窗口共享（替代旧版的 Pinia store 与跨 WebView 事件）：

```rust
pub struct AppState {
    pub todos: Vec<Todo>,              // 全部待办（含子任务）
    pub view_mode: ViewMode,           // 列表 / 四象限
    pub is_fixed: bool,                // 是否固定模式
    pub fixed_embed_desktop: bool,     // 固定模式时嵌入桌面
    pub is_dark_theme: bool,
    pub show_calendar: bool,
    // 字体、通知方式、同步状态、版本检查结果……
}
// 读：cx.observe(&state, ..) 让视图跟着刷新
// 写：create_todo / update_todo / toggle_complete / delete_todo / reorder_todos / …（后台执行，成功后更新本地副本）
// 拉取：fetch_todos（单飞 + 过期丢弃）、refresh_if_changed（5s 轮询变更计数）
```

### 2.3 控件与主题

- `ui/`：Element Plus 风格控件（按钮、输入框、下拉、开关、日期 / 时间选择、颜色选择、消息、确认框、Markdown 渲染与编辑……），每种只有一个实现
- `theme.rs`：颜色 / 字体 / 圆角 / 间距 / 阴影 token 的唯一来源

### 2.4 进程级服务（`services/`）

托盘 / 菜单栏图标、单实例、开机自启、同步编排与自动同步、提醒调度、系统通知、主窗口窗口模式（固定 / 嵌入桌面 / 贴边隐藏 / 位置记忆）、
桌面收纳箱生命周期、版本检查、日志；macOS 另有应用菜单与 Dock 唤起（`mac_menu.rs`）。

### 2.5 平台层（`platform/`）

GPUI 没有的窗口能力：按客户区读写物理像素几何、显示器枚举、置顶 / 显隐 / 任务栏样式、owner、嵌入桌面层（`embed.rs`）、
窗口子类过程（`subclass.rs`：永远置底、固定模式锁定几何）、系统取色与文件对话框。macOS 实现在 `macos/`（`ns.rs` 用 objc2 调 AppKit，
`mod.rs` 接到跨平台签名上），坐标换算在 `mac_geometry.rs`；Linux 上为 no-op 或近似实现（`fallback.rs`）。

## 3. 业务核心（crates/core）

### 3.1 模块结构

```
pc-gpui/crates/core/src/
├── lib.rs
├── db/                       # 数据库
│   ├── connection.rs         # 连接管理、迁移前备份、外键处理
│   ├── migrations.rs         # 数据库迁移（v1~v30，迁移表驱动）
│   ├── models.rs             # 数据模型
│   ├── settings_kv.rs        # settings 读写助手（只在值变化时刷新 updated_at）
│   ├── sync_store.rs         # 变更计数、墓碑、记录读写与合并
│   ├── time.rs               # 规范时间格式解析/规范化
│   ├── paths.rs              # 数据 / 图片目录、图片文件名校验
│   └── backup.rs             # VACUUM INTO 备份（保留最近 5 份）
├── services/                 # webdav.rs、secret.rs（DPAPI）、fence_fs/（收纳箱文件层）
├── todo.rs                   # 待办 / 子任务 CRUD、排序、图片保存、从文件导入子任务
├── data.rs                   # 导入导出、应用设置块
├── sync/                     # WebDAV 同步
├── settings.rs               # 单项设置、运行时偏好、屏幕配置
├── holiday.rs / lunar.rs     # 节假日、农历
├── reminder.rs               # 提醒调度纯逻辑、应用内通知窗口槽位
├── window_logic.rs           # 贴边隐藏状态机等纯逻辑
└── fence/                    # 桌面收纳箱元数据 / 几何 / 内容
```

### 3.2 主要函数

```rust
// 待办
pub fn todo::list(db: &Database) -> Result<Vec<Todo>, String>;
pub fn todo::create(db: &Database, req: &CreateTodoRequest) -> Result<Todo, String>;
pub fn todo::update(db: &Database, id: i64, req: &UpdateTodoRequest) -> Result<Todo, String>;
pub fn todo::delete(db: &Database, id: i64) -> Result<(), String>;
pub fn todo::reorder(db: &Database, ids: &[i64]) -> Result<(), String>;

// 数据导入导出
pub fn data::export_to_file(db: &Database, path: &Path) -> Result<(), String>;
pub fn data::import_from_file(db: &Database, path: &Path) -> Result<(), String>;

// 同步
pub fn sync::run(db: &Database, mode: SyncMode) -> Result<SyncReport, String>;
```

全部是阻塞函数，界面层用 `db::spawn_db(cx, |db| …)` 放到后台线程调用，结果回到前台更新 `AppState`。

## 4. 数据流

### 4.1 待办操作流程

```
用户操作 → 窗口视图 → AppState 方法 → spawn_db（后台线程）→ core 函数 → SQLite
                                                   ↓
界面刷新 ← cx.observe ← AppState 本地副本更新 ← 返回结果（回到前台）
```

### 4.2 通知提醒流程

```
┌─────────────────┐     ┌──────────────────┐     ┌──────────────────────┐
│ services::      │────▶│ reminder::run_due │────▶│ 系统通知（Toast）     │
│ scheduler       │     │ 检查到期提醒       │     │ / macOS 通知中心      │
│                 │     │                  │     │ 或应用内通知窗口      │
│（对齐整分钟）    │     │（后台线程）        │     │                      │
└─────────────────┘     └──────────────────┘     └──────────────────────┘
```

## 5. 依赖配置

依赖以 `pc-gpui/crates/core/Cargo.toml`、`pc-gpui/crates/app/Cargo.toml` 为准，主要有：

| crate | 用途 |
|---|---|
| `gpui-kit = "=0.7.3"` | GPUI 与 gpui-component（精确钉版本） |
| `rusqlite`（bundled） | SQLite |
| `reqwest`（blocking） | WebDAV、节假日数据 |
| `windows` | Win32（core 0.58：Shell / DPAPI / DirectWrite；app 0.62：窗口能力，与 gpui 同版本） |
| `tray-icon`、`notify-rust`、`auto-launch`、`rfd` | 托盘 / 菜单栏图标（Windows + macOS）、系统通知（notify-rust 只在非 mac 上编译）、开机自启、文件对话框（rfd 仅 Windows） |
| `objc2`、`objc2-foundation`、`objc2-app-kit` | macOS 的 NSWindow / NSScreen / NSEvent 调用（与 gpui-pre-macos 同版本） |
| `notify` | 收纳根目录监听 |
| `tyme4rs` | 农历 |

### 5.1 Windows 特殊功能

- **透明窗口**：GPUI 在 Windows 上用 DirectComposition 实现透明，主窗口 / 通知 / 收纳箱建窗时 `transparent = true`，界面自己画圆角底色
- **固定模式**：`WS_EX_TOOLWINDOW`（不进任务栏、不参与 Alt+Tab）+ 窗口子类过程拦截命中测试锁定位置与尺寸
- **嵌入桌面**：owner = Progman（`GWLP_HWNDPARENT`）+ 子类过程把每次 `SetWindowPos` 压到 `HWND_BOTTOM`，Win+D 时随桌面一起被抬起

### 5.2 macOS（预览，未经真机验收）

- **构建**：gpui-kit 开了 `runtime_shaders`，Metal 着色器运行时编译，构建只需要 Xcode Command Line Tools；arm64 runner 上一次构建 arm64 + x86_64，
  `lipo` 成 universal，组装 `mini-todo.app` 后整包 ad-hoc 签名，出 dmg（`pc-gpui/scripts/macos/`）
- **窗口**：GPUI 只能在建窗时给位置 / 层级 / 可缩放，运行时摆窗、显示隐藏、置顶、改 style mask 由 `platform/macos/ns.rs` 用 objc2 调 AppKit；
  `Hwnd` 是 NSWindow 的窗口号（每次重新查找）；物理像素 = 全局点坐标 × 所有屏的最大缩放（`mac_geometry.rs`）
- **固定模式**：`setMovable:NO` + 去掉可缩放，唤起时临时浮动层级；没有逐窗口的"不进程序坞 / ⌘Tab"，没有嵌入桌面
- **常驻与身份**：菜单栏模板图标（tray-icon）、应用菜单（`set_menus`，⌘Q / ⌘, / ⌘W 等）、Dock 唤起（`on_reopen`）；单实例、开机自启、日志、
  通知归属都沿用 2.5.0 mac 版的名字（见 `CLAUDE.md`「兼容旧版沿用的名字」）
